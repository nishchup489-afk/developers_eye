# Developers Eye — Source Registry Seed Plan

**Status:** Design specification  
**Phase:** Offline engine → Source Registry  
**Initial scope:** 3 documentation sources, 0 crawled pages  
**Owner:** `crawler/src/crawler/seed/`

## 1. What are we seeding?

We seed **source definitions** into PostgreSQL's `sources` table. A source definition tells the crawler *where to discover developer content* and *what boundaries to follow*.

**We do not seed:** every URL on a site, scraped HTML, extracted documents, search vectors, or historical crawl attempts. Those are created by later pipeline stages.

| Concept | Example | Stored in |
|---|---|---|
| Source definition | Python Documentation and its crawl policy | `sources` |
| Discovered fetch target | `https://docs.python.org/3/library/asyncio.html` | `crawl_frontier` |
| HTTP fetch outcome | Status code and duration | `crawl_attempts` |
| Extracted searchable page | Title, cleaned body, canonical URL | `documents` |
| Indexed text | PostgreSQL `tsvector` | `search_index` |

### Seed configuration example

This is a **logical payload** based on the current proposed `sources` model.

```json
{
  "slug": "python-docs",
  "name": "Python Documentation",
  "kind": "website",
  "base_url": "https://docs.python.org/3/",
  "allowed_hosts": ["docs.python.org"],
  "crawl_interval_seconds": 604800,
  "is_enabled": true,
  "config": {
    "seed_urls": ["https://docs.python.org/3/"],
    "allowed_path_prefixes": ["/3/"],
    "max_depth": 2,
    "max_pages_per_run": 100,
    "discovery_methods": ["seed", "html_links"]
  }
}
```

For the first batch, use equivalent configuration for FastAPI and MDN. The keys under `config` are **application-level conventions**; you must implement the corresponding logic in discovery. JSONB alone does not enforce limits.

## 3. What each source record must contain

| Field | Required meaning | Notes |
|---|---|---|
| `slug` | Stable source identifier | Unique; use for idempotent upserts |
| `name` | Display name | Human-readable |
| `kind` | `website`, `rss`, or `api` | Initially all `website` |
| `base_url` | Entry point | Not necessarily the only seed URL |
| `allowed_hosts` | Request host allowlist | Validate **every** redirect target, not only initial URLs |
| `crawl_interval_seconds` | Default revisit interval | Scheduler will enforce later |
| `is_enabled` | Activation switch | Disabled sources must not create new work |
| `config` | Source-specific crawl policy | JSONB: seeds, paths, depth and page caps |
| `created_at` | Insertion timestamp | Database default is appropriate |

`id` should be generated by PostgreSQL. Do **not** assign fixed integer IDs in the seed file.

Secrets such as API tokens must stay in environment/secret management, **not** in `sources.config`.

## 4. What happens after seeding?

```text
sources (3 rows)
    |
    v
Discovery reads enabled sources
    |
    v
Take config.seed_urls
    |
    v
Normalize URL + validate host/path + deduplicate
    |
    v
crawl_frontier (initial queued URLs)
    |
    v
Scheduler + frontier worker
    |
    v
Robots policy + per-host pacing + HTTPX fetch
    |
    v
HTML parsing + extraction
    |                     \
    v                      -> newly discovered links go back through validation
 documents
    |
    v
 indexer -> search_index
```

**Critical distinction:** registering 3 sources does **not** produce 3 documents. Even the first frontier targets will only exist after the discovery/initial-enqueue operation.

## 5. Expansion roadmap (do not seed as enabled yet)

|---|---|---|
| PostgreSQL documentation | SQL and database guides | Website discovery |

### Batch 3: Developer discussions and issues

| Candidate | Why it matters | Ingestion approach | Prerequisite |
|---|---|---|---|
| GitHub Issues | Real bugs, fixes, feature requests | Official REST API | Authentication/rate-limit design; issue vs PR filtering |
| Hacker News | Technical discussions and links | Official API | Item parsing and canonical URL handling |
| Reddit developer communities | Questions and developer discussions | Authorized API access | Review current access requirements, terms, quotas, and retention rights |
| Stack Overflow | Questions and answers | Official Stack Exchange API | Quotas, attribution, and license compliance |

Do **not** treat discussion platforms as ordinary unrestricted HTML crawl targets. Use permitted interfaces and review platform-specific restrictions before activation.

### Batch 4: Developer events

Potential categories: hackathons, meetups, conferences, CFPs. Register **specific verified feeds/APIs** rather than vague source names such as `all-events`. These need dedicated fields later, such as event start/end time, location, organizer and registration URL.

## 6. Initial safety and resource limits

Recommended development defaults, subject to each site's published rules:

- Maximum 100 fetched pages **per source per test run**.
- Maximum discovery depth of **2** from a configured seed (depth counts link hops).
- Run **one worker** initially and use conservative per-host pacing.
- Fetch and cache `robots.txt` correctly; don't assume all HTTP failures mean allow or deny.
- Respect HTTP `429`, `Retry-After`, and server errors with backoff.
- Restrict the scheme to `http`/`https` and enforce approved hosts after redirects.
- Reject non-HTML downloads for the website-only MVP unless deliberately supported.
- Skip login pages, account/private areas and site search-result loops.
- Set request timeout and maximum response size limits.
- Store canonical links to sources; do not assume permission to redistribute full copyrighted documents.

A policy field such as `max_pages_per_run` is only useful once your crawler actually enforces it.

## 7. Seeding implementation contract

Expected files (in your existing repository layout):

```text
crawler/
└── src/
    └── crawler/
        └── seed/
            ├── __init__.py
            ├── registry.py   # curated source definitions
            └── seed.py       # idempotent DB insert/upsert
```

**`registry.py`:** Defines the small, version-controlled list of approved source configurations.  
**`seed.py`:** Opens a database session, checks uniqueness by `slug`, inserts new records, and reports outcomes.

Your crawler can import the existing `backend` package containing SQLAlchemy models and DB session configuration, provided it is installed as a local dependency. Avoid copy-pasting SQLAlchemy models into the crawler package.

**Idempotency choice:** For the first implementation, insert missing slugs and leave existing records unchanged. Later, add an explicit `--update-existing` option so changes to production crawl policies are intentional.

## 8. Acceptance criteria

- [ ] Source model fields match the planned seed payload.
- [ ] Seeder inserts **3** active website sources on first run.
- [ ] Second run inserts **0** duplicates.
- [ ] No API credentials or secrets stored in the database configuration.
- [ ] All source hosts and scope restrictions are inspectable in PostgreSQL/DataGrip.
- [ ] Seeder does **not** fetch content or write to `documents`/`search_index`.
- [ ] Discovery can read enabled sources and extract `seed_urls` for future frontier enqueueing.
