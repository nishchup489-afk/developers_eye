# Fuzzy vocabulary and repair

Area: indexer · Status: active

## Purpose

Derives retained terms from stored text/code lexemes, counting documents rather than occurrences. The folder spelling is retained to avoid breaking existing links. The separate vocabulary worker was abandoned; a one-shot rebuild remains.

Reviewed against `facd333` on 2026-11-02. “Active” means implementation exists, not that it is integrated into every caller or production-verified.

## Open issues

INC-0007 remains open: multi-term additions overcount and indexer removal skips the shared mutex. The legacy vocabulary_document_state model has no active writer and its named migration is empty, so it is not proof of an installed table.

## Rules for future changes

- Do not tokenize document text to build the vocabulary; read lexemes from `search_index` (ADR-0002).
- Never delete `search_index` rows directly; use `remove_indexed_documents()` inside a transaction that holds `lock_vocabulary()` (ADR-0002).
- Take `lock_vocabulary()` before any `document` row lock (ADR-0002).
- Change `vocabulary_terms()` only together with a rebuild (ADR-0002).
- After manual SQL on `search_index` or `document`, run `python -m indexer.vocabulary_rebuild --once` with workers stopped.
- Keep passing: `indexer/tests/test_vocabulary.py`, `indexer/tests/test_service_writer.py`, `indexer/tests/test_indexer.py`.
- Fix incremental correctness before recounting and resuming writers.
- Do not reintroduce a permanent vocabulary worker without an ADR.
- Measure contention before replacing the mutex.
- Test multi-term additions, not just a one-term delta.
- Acquire the shared mutex before document locks on every index deletion path.
